# Implementation Plan: Source/Provider Abstraction

**Branch**: `010-source-provider-abstraction` | **Date**: 2026-05-10 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/010-source-provider-abstraction/spec.md`

## Implementation Recap

Extract ingestion source handling into a pluggable Source/Provider abstraction by defining a `Source` base class, `SourceConfig` Pydantic models for per-source configuration, and a `SourceRegistry` singleton factory. Refactor existing `read_dataframe()` logic in `upload_service.py` into `ExcelSource` and `CSVSource` subclasses to prove the abstraction. Wire the registry into the upload orchestration layer (`UploadApp`) and FastAPI startup to enable future data source types (databases, APIs, cloud storage) to be added as isolated subclasses without editing orchestration code. Preserve all existing upload behavior through byte-level output parity testing.

## Design Decisions

### Decision Gate A: YAML Descriptors and Auto-Discovery

**Status**: LOCKED OUT  
**Requirement (FR-016)**: This round must NOT introduce YAML descriptor loading or auto-discovery.  
**Design Impact**: All source registrations must be explicit (e.g., `SourceRegistry.register(ExcelSource)`) in backend startup code. Auto-discovery (via `@dataclass(sources/*.py)` or YAML config) is deferred to a future round (post-Phase-5 work).  
**Verification**: At Phase 5, verify that SourceRegistry setup code in `main.py` or `upload_app.py` contains exactly two explicit `register()` calls (ExcelSource, CSVSource) and no glob or YAML loader logic.

### Decision Gate B: Column-Mappings Hook (Pre-staging)

**Status**: LOCKED (pre-staged, no-op)  
**Requirement (FR-008)**: Source.post_commit_hook(workspace_id, source_file_id, columns) must be called after successful upload orchestration.  
**Design Impact**: The Source base class must define post_commit_hook() as a no-op (or as an overridable method). Orchestration code (UploadApp) must call the hook after profile computation. This establishes the call site for future fuzzy-matcher registration without breaking current upload flow.  
**Verification**: At Phase 2, verify that post_commit_hook() is defined in Source base class. At Phase 4, verify that UploadApp calls it. At Phase 5, verify that a test can override post_commit_hook() and observe the call without disrupting upload completion.

### Decision Gate C: No New Source Types

**Status**: LOCKED (Excel + CSV only)  
**Requirement (FR-004, FR-005)**: This round implements only ExcelSource and CSVSource.  
**Design Impact**: SourceRegistry initialization must register exactly two sources. DatabaseSource, SalesforceSource, etc. remain out of scope; they are future work.  
**Verification**: At Phase 5, SourceRegistry.list_sources() returns exactly 2 items.

### Design Decision D: Source Base Class Location and Naming

**Status**: DECISION REQUIRED (Phase 0 research)  
**Options**:

1. **Option A** (Preferred): `apps/backend/app/sources/base.py` (Source base class) + `apps/backend/app/services/source_registry.py` (SourceRegistry).  
   _Rationale_: Mirrors Round 23 pattern—orchestrators in `apps/`, services (factories) in `services/`, domain objects in dedicated domain module (`sources/`). Cleanly separates domain (Source subclasses) from factory (SourceRegistry).

2. **Option B**: `apps/backend/app/core/sources.py` (all Source + SourceRegistry + SourceConfig).  
   _Rationale_: Single-file simplicity; sources are framework-like (cross-cutting).

3. **Option C**: `apps/backend/app/services/sources/` (subdirectory: base.py, registry.py, excel.py, csv.py).  
   _Rationale_: Services own all data-access logic; sources are a special service.

**Recommended**: Option A—follows Round 23 conventions and enables future growth (more sources, plugins) without flattening the module hierarchy.

### Design Decision E: SourceRegistry Singleton Pattern

**Status**: LOCKED  
**Requirement (FR-006)**: SourceRegistry MUST be a singleton or thread-safe factory accessible from upload_service.py and endpoints.  
**Design Impact**: SourceRegistry is initialized at app startup (in `main.py` or `upload_app.py`) and exposed as a module-level singleton (similar to `AppConfig` in `shared.py`). Upload orchestration imports `from app.services.source_registry import SourceRegistry` and calls `SourceRegistry.for_type(type_str)` to fetch a Source instance.  
**Verification**: At Phase 4, verify that SourceRegistry singleton is importable and that multiple calls to `SourceRegistry.for_type("excel")` return Source instances (not necessarily the same instance, but consistent behavior).

### Design Decision F: Backward-Compatibility Validation Strategy

**Status**: LOCKED  
**Requirement (FR-007, SC-002, SC-003)**: ExcelSource.parse() and CSVSource.parse() must produce byte-identical DataFrame output to current `read_dataframe()`.  
**Design Impact**:

- Extract `read_dataframe()` logic into ExcelSource and CSVSource without modification (move, don't refactor).
- Create snapshot tests: for each test file (single-sheet, multi-sheet, mixed types), compute parquet hash pre-refactor and post-refactor; verify identity.
- Keep the original `read_dataframe()` in place during Phase 2-3 for side-by-side testing; remove it in Phase 4 after validation.

**Verification**: At Phase 3 (CSVSource), run side-by-side comparison of `read_dataframe()` output vs `CSVSource.parse()` output for all CSV test files. At Phase 4, verify that existing upload tests pass unchanged without being rewritten.

### Design Decision G: Error Handling Preservation

**Status**: LOCKED  
**Requirement (FR-018)**: Source.parse() failures MUST produce the same error feedback as current `read_dataframe()` failures.  
**Design Impact**: When ExcelSource or CSVSource fails to parse, the exception message and type must match pre-refactor behavior (e.g., "openpyxl failed: ...; calamine failed: ..." for Excel fallback). Orchestration code must not suppress or reinterpret errors.  
**Verification**: At Phase 3, create a test suite for error cases (corrupted Excel, ambiguous CSV delimiter, unsupported file type) and verify that error messages are identical to pre-refactor baseline.

### Design Decision H: SourceConfig as Pydantic Model

**Status**: LOCKED  
**Requirement (FR-010)**: SourceConfig subclasses MUST be Pydantic models or frozen dataclasses to enable eventual YAML descriptor support (Gate A deferred).  
**Design Impact**: Define `SourceConfig` as a Pydantic `BaseModel` with a `source_type: str` field. Each Source subclass has a corresponding config subclass (e.g., `ExcelSourceConfig`, `CSVSourceConfig`) that extends SourceConfig with source-specific fields. Configs are serializable (JSON/dict) to enable YAML support in a future round.  
**Verification**: At Phase 1, verify that all SourceConfig subclasses can be serialized to JSON and deserialized back without loss.

### Design Decision I: Integration Point — UploadApp Orchestrator

**Status**: LOCKED (Round 23 precedent)  
**Requirement (FR-007)**: upload_service.py MUST be refactored to call SourceRegistry instead of `read_dataframe()`.  
**Design Impact**: The orchestration logic currently in `UploadApp` (or split between `UploadApp` and endpoints) calls `read_dataframe()` to load a file. After refactoring, UploadApp calls `SourceRegistry.detect_source_type(filename)` → `SourceRegistry.for_type(type_str)` → `Source.parse(config)`. The orchestration layer remains unchanged; only the Source dispatch point changes.  
**Verification**: At Phase 4, verify that a test can mock SourceRegistry and inject a stub Source without modifying orchestration code.

**Duration Estimate**: 1-2 days (parallel: research + design)  
**Deliverables**: `base.py` (Source, SourceConfig classes), `source_registry.py` (SourceRegistry, SourceMetadata), `data-model.md`, `research.md`

**Goals**:

- Define SourceConfig Pydantic base class with source_type field.
- Define SourceRegistry factory with register(), for_type(), detect_source_type(), and list_sources() methods.
- Define SourceMetadata for introspection.
- Document the pattern (research.md) and entity relationships (data-model.md).

**Design Details**:

```python
# sources/base.py
from abc import ABC, abstractmethod
from dataclasses import dataclass
from pydantic import BaseModel
import polars as pl

class SourceConfig(BaseModel):
    """Extensible configuration base for all ingestion sources."""
    source_type: str

    class Config:
        frozen = True  # Immutable to enable YAML descriptor hashing

class Source(ABC):
    """Abstract base class for all ingestion sources."""

    @abstractmethod
    def parse(self, config: SourceConfig) -> pl.DataFrame:
        """Parse input data and return a Polars DataFrame."""
        pass

    @abstractmethod
    def compute_profiles(self, df: pl.DataFrame) -> list[ColumnProfile]:
        """Compute column profiles for the given DataFrame."""
        pass

    def post_commit_hook(
        self,
        workspace_id: str,
        source_file_id: str,
        columns: list[ColumnProfile]
    ) -> None:
        """Called after successful upload. No-op in this round; overridable for future use."""
        pass

@dataclass
class SourceMetadata:
    """Introspectable metadata about a registered source type."""
    source_type: str
    display_name: str
    description: str
    supported_extensions: list[str]
    requires_config: dict[str, Any] = None
```

**SourceRegistry API**:

```python
class SourceRegistry:
    """Factory and registry for Source subclasses."""

    @staticmethod
    def register(source_class: type[Source]) -> None:
        """Register a Source subclass by its source_type."""
        pass

    @staticmethod
    def for_type(source_type: str) -> Source:
        """Return a Source instance for the given type."""
        pass

    @staticmethod
    def detect_source_type(filename: str) -> str | None:
        """Infer source type from file extension."""
        pass

    @staticmethod
    def list_sources() -> list[SourceMetadata]:
        """Return metadata for all registered sources."""
        pass
```

**Verification Checkpoints**:

- ✓ Source base class can be imported without errors.
- ✓ SourceConfig can be instantiated and serialized to JSON.
- ✓ SourceRegistry can register a mock Source and retrieve it by type.
- ✓ detect_source_type() correctly identifies .xlsx, .xlsm, .csv files by extension.
- ✓ list_sources() returns empty list before any sources are registered.

**Risks**:

- **Circular imports**: If Source subclasses import SourceRegistry and SourceRegistry imports subclasses. **Mitigation**: Lazy imports in registry; registration happens at app startup, not at module load.
- **Missing ColumnProfile import**: Source.compute_profiles() returns a list of ColumnProfile, which must be imported. **Mitigation**: Import ColumnProfile in base.py from upload_service.py (or move it to a shared models module).

```python
# sources/excel_source.py
from io import BytesIO
from pydantic import Field
from app.sources.base import Source, SourceConfig

class ExcelSourceConfig(SourceConfig):
    source_type: str = Field(default="excel", frozen=True)
    filename: str
    file_bytes: bytes

class ExcelSource(Source):
    def parse(self, config: ExcelSourceConfig) -> pl.DataFrame:
        """Extract Excel-specific logic from read_dataframe()."""
        # Copied verbatim from read_dataframe() for Excel files
        try:
            return pl.read_excel(
                BytesIO(config.file_bytes),
                engine="openpyxl",
                raise_if_empty=False
            )
        except Exception as openpyxl_exc:
            try:
                return pl.read_excel(
                    BytesIO(config.file_bytes),
                    engine="calamine",
                    raise_if_empty=False
                )
            except Exception as calamine_exc:
                raise ValueError(
                    f"openpyxl failed: {openpyxl_exc}; calamine failed: {calamine_exc}"
                ) from calamine_exc

    def compute_profiles(self, df: pl.DataFrame) -> list[ColumnProfile]:
        # Reuse existing logic from upload_service.py
        ...
```

**Test Strategy**:

- Create baseline test: for each Excel file in test suite, capture parquet hash output from current `read_dataframe()`.
- Create refactor test: for each Excel file, run through `ExcelSource.parse()` and capture parquet hash.
- **Assertion**: baseline hash == refactor hash (byte-for-byte identity).
- Edge cases: single-sheet, multi-sheet, mixed types, empty sheets, encoding edge cases.

**Verification Checkpoints**:

- ✓ ExcelSource can be instantiated and registered with SourceRegistry.
- ✓ ExcelSource.parse() produces DataFrames identical (byte-wise via hash) to `read_dataframe()` for all test files.
- ✓ ExcelSource error handling produces identical error messages to `read_dataframe()` for invalid files.
- ✓ Existing upload tests pass without modification (orchestration still calls `read_dataframe()` during this phase).

**Risks**:

- **Subtle parsing differences**: Polars version, openpyxl version, or environment differences could introduce non-determinism. **Mitigation**: Run tests in CI/CD environment; use containerized test runners; snapshot tests must be deterministic within the same environment.
- **Fallback behavior divergence**: openpyxl → calamine fallback may not trigger identically if exception types differ. **Mitigation**: Test with files known to trigger fallback; capture both exception types in error message.

**Design Details**:

**upload_app.py change**:

```python
# Before
def process_upload(filename: str, file_bytes: bytes) -> UploadResult:
    df = read_dataframe(filename, file_bytes)
    columns = compute_column_profiles(df)
    ...

# After
def process_upload(filename: str, file_bytes: bytes) -> UploadResult:
    source_type = SourceRegistry.detect_source_type(filename)
    source = SourceRegistry.for_type(source_type)
    config = ExcelSourceConfig(filename=filename, file_bytes=file_bytes)  # or CSVSourceConfig
    df = source.parse(config)
    columns = source.compute_profiles(df)
    # ... orchestration continues (persist to parquet, etc.)
    source.post_commit_hook(workspace_id, source_file_id, columns)
    return UploadResult(...)
```

## Risks & Mitigations

### Phase 1 Risks

| Risk                                                                                         | Likelihood | Impact                              | Mitigation                                                                                           |
| -------------------------------------------------------------------------------------------- | ---------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Circular imports: Source subclasses import SourceRegistry, SourceRegistry imports subclasses | Medium     | High (refactor blocks)              | Use lazy imports in registry; registration happens at app startup, not module load                   |
| ColumnProfile import missing or causes circular dependency                                   | Low        | High (design must be redone)        | Move ColumnProfile to a shared models module (or import directly from upload_service) during Phase 1 |
| SourceRegistry design is too generic or too specific                                         | Low        | High (usability for future sources) | Validate design against hg_code/src/com/provider.py pattern; get code-review sign-off before Phase 2 |

### Phase 2 Risks

| Risk                                                                 | Likelihood | Impact                 | Mitigation                                                                                                                          |
| -------------------------------------------------------------------- | ---------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Breaking existing Excel upload during refactor                       | Medium     | High (release blocker) | Maintain byte-level output parity. Use comprehensive snapshot tests. Keep old `read_dataframe()` in place for side-by-side testing. |
| Fallback behavior (openpyxl → calamine) diverges between old and new | Medium     | High (data integrity)  | Test with files known to trigger fallback. Capture both exception types in error message. Run tests in containerized environment.   |
| Encoding or locale-specific parsing differences                      | Low        | Medium (edge cases)    | Snapshot tests must run in CI/CD environment; replicate environment in local dev if possible.                                       |

### Phase 3 Risks

| Risk                                                  | Likelihood | Impact              | Mitigation                                                                                                               |
| ----------------------------------------------------- | ---------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| CSV delimiter detection or encoding inference differs | Low        | Medium (edge cases) | Baseline and refactor test for ambiguous files (mixed delimiters, encoding hints). Snapshot tests must be deterministic. |

### Phase 4 Risks

| Risk                                                      | Likelihood | Impact                         | Mitigation                                                                                                                                    |
| --------------------------------------------------------- | ---------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| SourceConfig instantiation overhead breaks upload latency | Low        | Low (microseconds, negligible) | Profiling in Phase 5; if issues arise, cache config instances or pre-allocate.                                                                |
| Exception handling changes break API error responses      | Medium     | High (API regression)          | Ensure Source.parse() exceptions are identical type/message to `read_dataframe()`. Wrap in orchestration layer with identical error handling. |
| post_commit_hook() implementation breaks upload workflow  | Low        | High (release blocker)         | Implement as no-op first; test with override to verify hook is called without disrupting upload.                                              |
| AppConfig namespace for source configuration missing      | Low        | Medium (future work delay)     | Phase 4 assumes no config is needed; document as Phase 5 deliverable if needed.                                                               |

### Phase 5 Risks

| Risk                                                      | Likelihood | Impact                              | Mitigation                                                                                 |
| --------------------------------------------------------- | ---------- | ----------------------------------- | ------------------------------------------------------------------------------------------ |
| Parquet hash snapshot tests non-deterministic across runs | Medium     | High (test fails spuriously)        | Use containerized test runner; make snapshots deterministic within CI/CD environment.      |
| CRG analysis unavailable or incomplete                    | Low        | Medium (coupling analysis deferred) | Use manual import graph inspection or alternative static analysis tool if CRG unavailable. |
| Incomplete test coverage for edge cases                   | Medium     | High (post-release bugs)            | Comprehensive Phase 5 edge-case test suite; do not defer edge cases to production.         |
