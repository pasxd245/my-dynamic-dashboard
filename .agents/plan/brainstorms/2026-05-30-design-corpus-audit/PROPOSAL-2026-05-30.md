# Proposal: Design-corpus conformance audit — shape + open decisions

_Recorded 2026-05-30 from the conversational brainstorm. This is the
agent's proposed shape; the three open decisions at the end are the
user's to settle._

## Goal

Sweep the flow doctrine ([hybrid-flow-governance](../../../decisions/2026-05-28-hybrid-flow-governance.md))
across the **8 live design surfaces** under
[.agents/design/data-management/](../../../design/data-management/) —
`crud-hygiene`, `dataset-detail`, `dataset-filters`, `datasets`,
`upload`, `workspace-shell` (+ `workspace-shell.target`), `workspaces`
— one per round, pausing each at review to confirm/fix.

- **Stated goal**: cross-surface consistency ("make all in-sync").
- **Real goal**: detect **missing-points in the method**, so they
  become concrete Evolution-Rule pulls — not vague unease.

## Reframe — and the first method-gap it exposes

DCFBI is a **delivery** chain (D→C→F→B→I for *building*). These
surfaces are **already shipped** at MVP close — there is nothing to
build. So the chain runs as a **conformance audit**:

- **D** → does the doc meet the Design-gate exit criteria + the
  [design README](../../../design/README.md) format (Surface-declaration
  table, token map, ASCII layout, behavior, scope boundary)?
- **C / F / B / I** → become **verification** gates: does the *shipped*
  contract / FE / BE / conformance-test still match what the doc
  declares?

That mismatch is itself **gap #1**: the doctrine is written for *new
feature rounds*, not for *auditing already-shipped surfaces*. Its own
`revisit-trigger` anticipates "an artifact category this doctrine did
not anticipate" — a retro-audit pass is one. The program surfaces a
real hole on day one. Good sign for the detection goal.

## Instruments already exist (Evolution-Rule-friendly)

Almost no new scaffolding — the audit *reuses the existing Track-2
skills as probes*, and their failures/awkward-fits ARE the method-gaps:

- **`ui-design` design-spec mode** — "does the doc DECLARE the six
  UX-honeycomb affordances," meant to run *at the Design gate*. Primary
  per-surface probe.
- **`gate-walker` / `flow-selector`** — retro-classify each surface
  (which flow *would* it have taken; does its doc satisfy each gate's
  exit criterion).
- **`markdown-check-link`** — cross-doc link/heading integrity (the
  horizontal probe).

Running the method's own instruments against real docs is the best way
to detect the instruments' gaps. Stays inside
[R99 evo-horizon](../../../decisions/2026-05-27-r99-evo-horizon.md)
(artifact-only, Track-2).

## Two axes — the best pulls live on the second

- **Vertical** (per doc): conforms to README format + Design gate +
  O-rule traceability. Mostly mechanical.
- **Horizontal** (across docs): shared **vocabulary**, token map,
  naming, cross-links, surface-declaration semantics all *agree*. This
  is the word "**in-sync**," and where the richest gaps hide. R55
  already coughed one up — *"vocabulary drift guarded by hand-mirrored
  tests"* (`OPS_BY_DTYPE` edited in four places by hand). A horizontal
  sweep finds the *class* of that bug, not just the instance.

## Mechanism — so "detect → pull in" actually pays off

Detection only pays off if findings are **comparable across surfaces**:

1. **One fixed rubric**, applied identically to every surface (the
   gate/facet checklist above). Same questions, every doc.
2. **One rolling gap-log** that accumulates across rounds (program-level,
   like R55's "candidate seeds" but spanning the chain). The signal:
   *a gap in 6/8 surfaces is a strong Track-2 pull; one in 1/8 is
   surface-local.* Invisible without the rollup.
3. **Firewall (round-cadence trap):** an audit will find the *UX
   itself* is weak, not just the doc, and balloon into a redesign.
   Rule — audit rounds emit (a) doc-conformance fixes in-round, and
   (b) **logged** product/UX gaps deferred to their own feature rounds.
   Never redesign inside an audit round. Same discipline as R55's
   "don't bundle."

## Sequencing instinct

- **advanced-query = the gold-standard exemplar.** Don't re-audit it;
  it's the template for "conformant" after R51/54/55. Score every other
  surface *against* it.
- **Round 1 is a pilot that calibrates the rubric.** Its "pause at
  review to confirm/fix" is partly *fixing the rubric* — you won't get
  the checklist right until it meets a real messy doc. Round 1's output
  = one surface audited **+** a hardened rubric.

## The three decisions — DECIDED (user, 2026-05-31)

All three settled with the suggested answers.

### 1. First surface / audit order

- **Decided (user, 2026-05-31): pilot on `dataset-filters`.** It's adjacent to
  advanced-query, so the exemplar transfers cleanly and the rubric gets
  calibrated against a doc that shares vocabulary with the gold
  standard (maximizes horizontal-axis signal early).
- Alternative: foundational-first (`workspace-shell` / `datasets`),
  since dependents inherit their vocabulary — stronger if the priority
  is propagating fixes downward, but a harder doc to calibrate on.

### 2. Depth

- **Decided (user, 2026-05-31): doc-conformance + spot-verify shipped artifacts.**
  Pure doc-conformance is a fast cheap sweep but weak detection; full
  C/F/B/I re-verification per surface is slow. Middle path: audit the
  doc against doctrine **and** spot-check the highest-risk
  traceability claim per surface (one contract↔doc or test↔doc link),
  which is where real drift (and the strongest method-gaps) lives.

### 3. Artifact shape

- **Decided (user, 2026-05-31): a single program doc** (the rubric + the rolling
  gap-rollup) that seeds per-round audit docs — the master-plan-style
  three-artifact contract. The rollup is precisely what makes the
  cross-surface pattern (and thus the concrete pulls) visible; per-round
  docs alone would scatter the findings.

## Method-gaps already surfaced (seed the rollup)

These came out of R51→R55 before the audit even starts — early evidence
the detection approach yields concrete pulls:

- **Vocabulary drift via hand-mirrored copies** — FE/BE `OPS_BY_DTYPE` + two test copies edited in lock-step (R55 § candidate seeds).
  _Horizontal axis._
- **Test selectors not contracted** — text-based test broke on a copy
  change, fixed via `data-component`. Lesson for the **C-method**:
  decide stable `data-component` / `data-id` hooks at the Contract gate
  as part of execution-truth (O-rule) → tests stop coupling to copy,
  future Playwright binds to stable hooks (adaptive, low-effort).
  (R55 § candidate seeds, user-noted 2026-05-30.) _C-gate facet of the
  rubric._
- **Doctrine assumes new-build, not audit** — gap #1 above. _D-gate /
  doctrine facet._
